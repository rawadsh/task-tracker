## Reconciliation

### Agreement

- **SEC-01 (no auth) + independent CORS read.** `main.py:30-36` sets `allow_credentials=False` with `allow_methods=["*"]`. Since credentials are off, browsers still enforce the origin allow-list for JS callers, but any non-browser client (curl, another service) can hit every route directly — CORS was never doing authorization here, consistent with SEC-01's framing.
- **SEC-02 (unbounded fields).** Independently confirmed the same absence of a `field_validator` on `description`/`assignee`, and it compounds with MAN-04: a corrupted `null` value isn't bounded by anything either, because it never passes through the length check at all.

### AI-only

- **SEC-03 (`/version` leak), SEC-04 (dependency floors), SEC-05 (Actions tag pinning)** — all correct, and all surfaced from reviewing config/infra surface (CI, Dockerfile, `requirements.txt`) that a logic-focused manual pass over `models.py`/`storage.py`/`main.py` wouldn't naturally cover. Genuinely additive.

### You-only

- **The null-PATCH cascade (MAN-01/02/03)** and its **root cause (MAN-04)** — the AI findings never touch the actual PATCH/model validation logic; SEC-02 is about missing length limits, not missing null-rejection, which is a distinct gap.
- **The test-coverage gap (MAN-05)** — zero null-PATCH coverage anywhere in the suite.
- **Dead `APP_ENV` (MAN-06)** and **XSS ruled out (MAN-07)** — neither app-layer config hygiene nor the frontend were in the AI pass's scope at all.
